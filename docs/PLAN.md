# PLAN — PDF → Markdown Skill

> 状态：**M1 与 M2 已实现并跑通真实链路**（2026-10-27）。剩余工作见 §8 验收表与[docs/ROADMAP.md](ROADMAP.md)。

## 1. 核心目标（原始需求）

> 一个以 skills 为形式，目的是将利用 mineru api + 模型 api 将 pdf 转换成 md 格式的文件（要求保留文件结构 + 图片，可选翻译）

拆成四条必须同时满足的要求：

| 编号 | 要求 | 可验收的判据 |
|---|---|---|
| R1 | **形态是 Skill** | 一个 Pi 能发现、能按 `description` 触发的 skill 包；`references/` 渐进加载；确定性动作落在 `scripts/` |
| R2 | **MinerU API + 模型 API 两段式** | OCR 走 MinerU 云接口；翻译走 OpenAI 兼容接口；两者都不在本机跑模型 |
| R3 | **保留文件结构 + 图片** | 标题层级/表格/公式/阅读顺序不被改写；每张图落到 `images/`，md 内相对引用可解析、可解码 |
| R4 | **翻译可选** | 默认不翻译也能产出完整交付；开启翻译后结构不变、图片序列与英文一致 |

## 2. 范围

### 2.1 做

- 单个 PDF → 一个自包含目录（md + 可选中文 md + 原 PDF + `images/`）
- 精准解析通道（需 Token，能拿图片与结构 JSON）
- 轻量解析通道（免 Token，纯 Markdown，图片缺失必须明说）
- 可选翻译：分块、并发、检查点续跑、失败不产出伪完成文件
- 交付前硬校验：图片存在/可解码/无外链/中英图片序列一致
- 凭据自检（doctor）与清晰失败信息

### 2.2 不做（明确排除）

- ❌ 版式复刻：不做 PDF 双栏绝对定位、不承诺视觉一致
- ❌ 本地模型推理：不装 `torch`、不跑本地 `mineru` CLI
- ❌ WebUI：本阶段无 Gradio 界面
- ❌ DOCX / EPUB / LaTeX 导出：`extra_formats` 能力先不用
- ❌ 改动 `main` 分支的冻结 runtime（本次全部工作在 `rewrite/v2`）
- ❌ 修复旧 `pi-paper-translator` 对 `pdf_to_zh_md.py` 的失效调用（另一个议题，见 §10）

## 3. 为什么是 Skill，不是 Python 包

| 维度 | Python 包（旧方案） | Skill（本案） |
|---|---|---|
| 触发 | 用户必须记住命令行 | `description` 就是触发面，agent 自己判断该不该用 |
| 上下文成本 | 全部代码/文档常驻或零散 | `SKILL.md` 常驻，`references/` 按需读 |
| 执行 | 需要安装、需要环境 | `scripts/` 直接跑，参数由 skill 决策后传入 |
| 失败处理 | 抛异常/退出码 | skill 规定「怎么判断失败、怎么说、下一步做什么」 |

代价：skill 必须写清**触发边界**（什么情况不该用）和**失败报告格式**，否则会误触发或谎报成功。这两条写进 M4 验收。

## 5. 产品契约

### 5.1 输入

| 输入 | 形式 | 说明 |
|---|---|---|
| PDF | 本地绝对路径 | 单文件；批量见 M3 |
| 目标语言 | 可选 | 不指定则只产出英文 md |
| 输出根目录 | 可选 | 默认与源 PDF 同级 |
| 通道 | 可选 | `precision`（默认）/ `flash` |
| 翻译开关 | 可选 | 默认关 |

### 5.2 输出（拟定契约，M1 定稿）

```
<out>/<stem>/
├── <stem>.md            # MinerU 原始 Markdown，图片链接已改写为 images/...
├── <stem>_zh.md         # 中文翻译；未翻译时不存在
├── <stem>.pdf           # 源 PDF 副本
├── images/              # 归一化图片，扩展名与真实编码一致
└── _meta/
    ├── manifest.json    # 来源 sha256、通道与参数、图片清单（含尺寸/哈希）
    ├── validation.json  # 校验结果（issues/warnings）
    └── content_list.json # MinerU 结构 JSON（若通道提供）
```

设计理由：

- `images/` 单独一层：md 里统一写 `images/xxx.ext`，移动目录不破链
- `_meta/` 隔离审计产物：阅读目录只留 md + pdf + images
- 不写 `_en.md` 后缀：英文版就是 `<stem>.md`，中文版用 `_zh.md` 区分，避免两个「原版」并存
- 运行态文件（缓存、检查点、临时文件）**一律不进交付目录**

### 5.3 「保留文件结构」的准确含义

保留的是**文档结构**，不是版式：

| 保留 | 不保留 |
|---|---|
| 标题层级（`#` 数量与原文一致） | 字体、字号、页边距 |
| 阅读顺序（单栏/多栏由 MinerU 决定） | 双栏绝对定位 |
| 表格（Markdown 表格 + 分隔符） | 表格线宽/底色 |
| 公式（LaTeX 原样，含行内 `$...$` 与块级 `$$...$$`） | 公式渲染样式 |
| 图片位置（在正文中的出现顺序） | 图片在页面上的坐标 |
| 列表、引用块、代码块 | 缩进像素值 |

另一个可能的意思——「批量时镜像输入目录树」——本阶段不做，列进 M3 的可选项。

### 5.4 通道选择（本项目的硬约束）

| 通道 | 适用 | 限制 | 图片 | 结构 JSON |
|---|---|---|---|---|
| `precision`（默认） | 论文、需要图片、需要结构 | 需 Token，≤200 MB / ≤200 页 | ✅ zip 内含 | ✅ |
| `flash` | 纯文本、快速预览、无 Token | ≤10 MB / ≤20 页 ⚠️（官方文档自相矛盾） | ❌ 只有 Markdown | ❌ |

⚠️ **「保留图片」这条要求只有 precision 能满足。** 因此 `flash` 不是降级备选，而是**另一种交付**：必须显式告知用户「本次无图片、无结构 JSON」，不能静默当成功。

### 5.5 翻译（可选）

| 决策 | 取值 | 理由 |
|---|---|---|
| 默认 | 关闭 | 需求是「可选」，默认不花模型额度 |
| 模型 | OpenAI 兼容 `chat.completions` | 兼容 MiniMax/DeepSeek/OpenRouter/本地 |
| 分块 | 按空行切，≤N 字符 | 保持段落边界 |
| 不许切开 | 代码围栏、块级公式、表格 | 切开会破结构（旧实现已验证） |
| 并发 | 默认 8 | 远端限流下的折中 |
| 续跑 | 每块落检查点，指纹含源文件+模型+参数 | 中断不重花额度 |
| 失败 | 保留英文、保留检查点、**不写** `_zh.md` | 不允许出现「看似完成」的中文文件 |
| 翻译后校验 | 中英图片引用数量与顺序一致 | 顺序错＝译文改写了结构 |

## 6. 架构与脚本职责

原则：**脚本负责确定性，SKILL.md 负责判断与表达。** 不让模型每轮手写 HTTP 调用。

| 脚本 | 职责 | 失败语义 |
|---|---|---|
| `scripts/mineru_client.py` | 两条通道的提交/上传/轮询/下载/解包（含 zip-slip 防护） | 抛带错误码的异常，不吞 |
| `scripts/organize.py` | 图片归一化（真实编码嗅探）、链接重写、交付目录组装、manifest | 路径越界/软链接 → 直接失败 |
| `scripts/validate.py` | 交付硬校验，产出 `validation.json` | 任一硬校验失败 → 退出码非 0 |
| `scripts/translate.py` | 分块、并发、检查点、模型调用、结构保护 | 空响应/失败 → 保留现场并报错 |
| `scripts/pdf2md.py` | 编排 + 命令行参数 | 统一退出码：0 成功 / 1 阶段失败 / 2 用法错误 |
| `scripts/doctor.py` | 凭据与连通性自检 | 缺 Token / key 时给出可执行的修复路径 |

## 7. 关键决策（含被否掉的方案）

| 编号 | 决策 | 备选与否决理由 |
|---|---|---|
| D1 | 走 MinerU **云 API** | 本地 `mineru` CLI 需 torch（约 1.8 GB）且 Mac 上慢；云 API 免部署 |
| D2 | 以 **Markdown 里的图片引用**为准定位图片 | 按 MinerU 文件名匹配：命名随版本变化（4.0 已改成 `page_{idx}_...`），不可靠 |
| D3 | 交付前**硬校验**，失败即失败 | 只警告：用户会拿到打不开图的 md，比报错更糟 |
| D4 | 凭据顺序：显式参数 > `.secrets/*.json` > 环境变量 > `.env` | `.secrets` 优先于环境变量：shell 里常驻过期 key（旧项目实测踩坑） |
| D5 | 缓存键 = 源文件 sha256 + 通道参数指纹 | 只按文件名缓存：同文件名换内容会拿到旧结果 |
| D6 | 不做 WebUI | 主要消费方是 agent；UI 是额外维护面，等 M5 再议 |
| D7 | 输出用 `_meta/` 而非顶层散落 json | 阅读目录保持干净；旧项目顶层 `manifest.json` 与 `_mineru/` 混杂 |

## 9. 风险与未验证项

| 风险 | 影响 | 处理 |
|---|---|---|
| ⚠️ 官方文档轻量接口页数 20 vs 错误示例 50 矛盾 | 通道选择判断可能错 | **已实测定案：真实上限 20 页**（44 页文件报 20 页超限）；`--pages` 可绕过 |
| 账号 1000 页/天配额未实测 | 批量可能被限速 | 压测累计仅约 80 页，未触发；超额影响仍未知 |
| 翻译端点并发上限未知 | 高并发可能被限流 | 实测 16 并发×3000 字无 429；429 退避由本地 stub 确定性验证 |
| MinerU 结果 zip 内部命名随版本变化 | 依赖命名会碎 | D2：只信 md 引用 |
| 大文件（>10 MB）无 Token 时完全不可用 | 用户拿不到图片 | doctor 明确报错 + 给申请 Token 的链接 |
| 排队时间不可控 | 超时误判为失败 | 轮询超时单独报错，不当作解析失败 |
| 本 worktree 已按指令删除 `.env` / `.secrets` | 无法实跑 | 已重建仅含测试凭据的 `.secrets/pdf2md.json`（`.gitignore` 覆盖，不入库） |
| 中文译文可能改动表格列数/公式 | 结构被破坏 | 翻译后校验图片序列 + 抽查表格 |

## 10. 与旧项目的关系
`main@bd6d939` 是一套 2964 行的 Python 包（CLI + WebUI + 契约测试），其中**被真实验证过的行为**是本项目的输入：

- 图片归一化与引用重写规则
- 六类硬校验（缺图、外链、非便携路径、扩展名不符、不可解码、中英序列不一致）
- 分块时不在代码围栏/块级公式内切开的做法
- 翻译检查点与指纹失效
- 凭据解析顺序

不移植：`argparse` 外壳、Gradio UI、console scripts、冻结的 runtime 文件。

另有一个已存在的坏链接：`pi-paper-translator` 的 `pdf_translate` 工具调用 `<project>/pdf_to_zh_md.py`，该脚本在 `3f1bb20` 被删除，**当前不可用**。是否恢复兼容层不在本次范围，需要单独决定。
